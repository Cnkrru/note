## 简介

浏览器环境下 JavaScript 运行机制相关的笔记，包括 BOM、垃圾回收、单线程与异步、DOM 树。

## 1. BOM

### 1.1 理论

- BOM（Browser Object Model）是浏览器对象模型
- 顶级对象：window
  - window 是全局对象，也是 JavaScript 中的顶级对象
- 特性
  - navigator、location、document、history、screen 等都挂在 window 下
  - 顶层用 `var` 声明的变量和函数声明会成为 window 的属性/方法，`let`、`const`、`class` 不会
  - 一个窗口就是一个 window 对象实例
- DOM 是独立的规范，只是 `document` 挂在 window 下

### 1.2 结构

```text
BOM (浏览器对象模型)
├── window (顶级对象)
│   ├── navigator (浏览器信息对象)
│   ├── location (地址栏对象)
│   ├── document (文档对象)
│   ├── history (历史记录对象)
│   └── screen (屏幕对象)
```

## 2. 垃圾回收机制

- 有了垃圾回收就不用手动管理内存，代价是会牺牲一点效率
- 常见策略
  1. 标记清除
     - 变量进入环境时标记为“进入环境”，离开环境时标记为“离开环境”，之后回收不再被引用的对象
     - 现代引擎更准确的说法是从根对象出发做可达性分析，不可达的对象才会被回收
  2. 引用计数
     - 记录每个值被引用的次数，次数变为 0 时回收
     - 缺点是无法处理循环引用，所以现代引擎主要以标记清除为主

## 3. 单线程与异步

### 3.1 单线程

- 主线程同一时间只能做一件事
- 好处是不会出现多线程同时写同一片内存的数据竞争问题
- 浏览器本身还有其他线程，定时器、I/O、网络请求等由它们处理

### 3.2 异步

- 把 I/O 等耗时操作交给浏览器，完成后通过回调放回任务队列，避免阻塞主线程
- 要注意事件可能先于数据到达，处理好时序

### 3.3 任务执行顺序

1. 调用栈：执行同步 JS 任务
2. 微任务队列：`Promise.then`、`queueMicrotask`、`MutationObserver`
3. 宏任务队列：`setTimeout`、`setInterval`、I/O、DOM 事件回调
- 每执行完一个宏任务，都会清空一次微任务队列，然后再取下一个宏任务
- 栈走同步，队列走异步，异步任务在同步任务执行完后才会被处理

## 4. DOM 树

- DOM 是 BOM 之外独立的规范，`document` 是它挂在 window 下的入口
- HTML 标签被解析成节点，节点组成 DOM 树，不是 document 的属性
- `document.documentElement`、`document.body` 等只是访问树中节点的入口
